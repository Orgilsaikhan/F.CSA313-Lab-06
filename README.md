## Хэсэг A: Category-Partition гараар — `POST /transfer`

```
POST /transfer  { "from": ID, "to": ID, "amount": NUM, "currency": CODE }
```

Код байхгүй, зөвхөн тодорхойлолт (shift-left). Тест бүрийн setup-ыг доорх суурь өгөгдлөөр тайлбарлана:

| Данс | Валют | Үлдэгдэл | Өдрийн лимит | Төлөв |
|---|---|---|---|---|
| `A100` | MNT | 500,000 | 1,000,000 | идэвхтэй — гол илгээгч |
| `B200` | MNT | 0 | 1,000,000 | идэвхтэй — гол хүлээн авагч |
| `F300` | MNT | 500,000 | 1,000,000 | **царцаагдсан** |
| `U400` | USD | 100 | 1,000 | идэвхтэй — USD данс |
| `X999` | — | — | — | **байхгүй** (ямар ч тест үүсгэдэггүй) |

Ханш: **1 USD = 3,500 MNT** (тест бүрт тогтмол гэж үзнэ).

### Алдааны давуу эрэмбэ

Тодорхойлолтод бичээгүй тул өөрөө тогтоосон:

```
ERROR_NO_FROM → ERROR_FROZEN → ERROR_NO_TO → ERROR_SAME_ACCOUNT → ERROR_BAD_AMOUNT → ERROR_INSUFFICIENT → ERROR_LIMIT
```

**Үндэслэл:** үлдэгдэл, лимит, валют бүгд `from` дансны өгөгдөл тул `from`-ийг эхэлж, дараа нь `to`-г, хамгийн сүүлд эдгээрээс хамаардаг `amount`-ыг шалгах ба `amount` дотроо данснаас хамааралгүй тэмдгийн шалгалт (`BAD_AMOUNT`) → одоогийн үлдэгдэл (`INSUFFICIENT`) → өдрийн хуримтлагдсан дүн (`LIMIT`) гэж хялбараас нь төвөгтэй рүү явна — Лаб 5-ын сервер ч мөн эхлээд оюутныг, дараа нь хичээлийг шалгадаг байсан.

### "N → M" тооцоо

**N — хязгаарлалтгүй бүрэн олонлог:** C1(3) × C2(4) × C3(3) × C4(3) × C5(3) × C6(2) × C7(2) × C8(2) = **2592**.

**IF хязгаарлалтын дараа:**

- C1 = байхгүй (FROM_EXISTS биш): C4–C8 утгагүй → C2(4) × C3(3) = **12**
- C1 ∈ {хүчинтэй, царцаагдсан}: C2(4) × C7(2) × (C6, C8)(ижил 1 + өөр×2 = 3) × [C3 ∈ {сөрөг, тэг} (2) + C3 = эерэг × C4(3) × C5(3) (9)] = 4 × 2 × 3 × 11 = 264, × 2 = **528**
- Нийт: 12 + 528 = **540**

**ERROR, SINGLE-ийн дараа:** [ERROR] 8 утга → 8 frame, [SINGLE] 3 утга → 3 frame. Үлдсэн хэвийн утгууд: C1 хүчинтэй × C2 өөр данс × C3 эерэг × C4 бага × C5 бага × (C6, C8) 3 × C7 2 = 6 frame. Нийт 6 + 8 + 3 = **17**.

```
2592 → 540 (IF) → 17 (ERROR, SINGLE)
```

|---|---|---|---|---|---|
| 2-way (анхдагч) | `results/browser-2way.txt` | **10** | 81 хос | 3 × 3 = 9 | 144 |
| 3-way (`/o:3`) | `results/browser-3way.txt` | **20** | 248 гурвал | 3 × 3 × 2 = 18 | 144 |

`/s` (статистик)-ийн гаралт `results/browser-stats.txt`-д. Бүрэн олонлог = 3 × 3 × 2 × 2 × 2 × 2 = **144**.

**2-way: 10 мөр — лекцийн 9-өөс нэгээр олон.** 9 бол онолын доод хязгаар: зөвхөн `Content × Cookies` гэхэд 3 × 3 = 9 хос байх ба мөр бүр тэдгээрийн яг нэгийг л хамардаг тул лекц дээр бүх 81 хосыг гараар 9 мөрөнд багтаасан. PICT нь **greedy** алгоритм — мөрийг нэг нэгээр нь байгуулж, тухайн агшинд хамгийн олон хамрагдаагүй хосыг барих утгуудыг сонгоод, өмнөх мөрүүдээ буцаж зөөж тохируулдаггүй тул хурдан, тогтвортой (ижил модель → ижил гаралт) боловч хамгийн цөөн мөрийг **заавал** олдоггүй. Үүнийг гаралт дээр шууд харж болно: 11-р мөр (`Allow Block Yes Yes Yes No`) зөвхөн ганц хос — `(Content = Allow, Attacks = Yes)` — -ыг шинээр хамардаг бөгөөд түүний `(Allow, Block)` хос 5-р мөрөнд аль хэдийн байсан, өөрөөр хэлбэл greedy-ийн "үлдэгдэл" хос нэмэлт мөр шаардсан.

**3-way: 20 мөр** — бүрэн олонлог 144-ийн **13.9%** (20 / 144), гэхдээ онолын доод хязгаар 3 × 3 × 2 = 18-аас мөн 2-оор олон. 2-way-ээс 3-way руу шилжихэд мөр 2 дахин өссөн ч бүрэн олонлогоос 7 дахин цөөн хэвээр — combinatorial тестийн гол давуу тал.

### B2 — Шилжүүлгийн модель

Хэсэг A-гийн сонголтуудыг PICT-ийн 5 параметр болгож буулгасан: C1 → `From`, C2 → `To`, C3–C5 → `Amount` (тэмдэг, үлдэгдэл, лимитийг нэг параметрт), C6 → `Currency`, далд орчны C7 → `DailyUsed`.

| Файл | Юугаараа ялгаатай |
|---|---|
| `transfer-nc.model` | Хязгаарлалтгүй |
| `transfer.model` | A2-ын **[IF FROM_EXISTS]** хязгаарлалт: `From = Missing` бол `Amount ∈ {Zero, Normal}`, `Currency = Same`, `DailyUsed = None` |
| `transfer-neg.model` | A2-ын **[ERROR]** утгууд `~`-тэй + [IF FROM_EXISTS] (`Currency`, `DailyUsed`-ийн хэсэг) |
| `transfer-neg-noif.model` | Харьцуулалтад: `transfer-neg.model`-оос IF хязгаарлалтыг хассан |

`transfer.model`-ийн хязгаарлалт:

```
IF [From] = "Missing" THEN [Amount] IN {"Zero", "Normal"} AND [Currency] = "Same" AND [DailyUsed] = "None";
```

Зааврын жишээний `IF [To] = "Missing" THEN [Amount] = "Normal"`-ийг оруулаагүй: `to` байхгүй байсан ч `from`-ийн үлдэгдэл, лимит байгаа тул `OverBalance` утга утгагүй болохгүй — энэ нь A2-ын IF биш, алдаа алдаагаа далдлах (masking) асуудал бөгөөд үүнийг `~` шийднэ. `Missing` дансны `Currency`, `DailyUsed`-д "хамаагүй" гэсэн утга байхгүй тул `Same`, `None`-д түгжсэн (PICT-ийн баримт бичгийн "dummy value technique"-ийн хялбар хувилбар).

PICT модельд **оруулаагүй** зүйлс: [SINGLE] утгууд (C2 царцаагдсан `to`, C4/C5 яг тэнцүү) — PICT-д "нэг л удаа" гэсэн тэмдэглэгээ байхгүй; C3 сөрөг (`Zero`-той ижил анги); C8 ханшийн чиглэл (`Currency = Different` дотор). Эдгээрийг гараар хийсэн A3-ын S7, S10–S15 хамарна.

```bash
pict transfer-nc.model       > results/transfer-nc.txt
pict transfer.model          > results/transfer.txt
pict transfer-neg.model      > results/transfer-neg.txt
pict transfer-neg-noif.model > results/transfer-neg-noif.txt
```

#### Гурван хувилбарын харьцуулалт

"Алдаа" = `From ∈ {Frozen, Missing}`, `To ∈ {Missing, SameAsFrom}`, `Amount ∈ {Zero, OverBalance, OverLimit}` тус бүр 1. "Утгагүй мөр" = `From = Missing` байхад `Amount ∈ {OverBalance, OverLimit}`, `Currency = Different` эсвэл `DailyUsed = Partial`. Мөрийн дугаар нь файлын мөр (толгой = 1-р мөр, `sed -n 'Np'`).

| Хувилбар | Мөр | Happy path мөр | Нэг мөр дэх алдаа (макс) | Алдааны тоогоор мөр (0 / 1 / 2 / 3) | Утгагүй мөр |
|---|---|---|---|---|---|
| `results/transfer-nc.txt` | **14** | 1 (мөр 14) | **3** | 1 / 2 / 7 / 4 | 3 (мөр 3, 8, 11) |
| `results/transfer.txt` | **14** | **0** | **3** | 0 / 3 / 7 / 4 | 0 |
| `results/transfer-neg.txt` | **18** | 4 (мөр 2–5) | **1** | 4 / 14 / 0 / 0 | 0 |
| `results/transfer-neg-noif.txt` | 18 | 4 (мөр 2–5) | 1 | 4 / 14 / 0 / 0 | 2 (мөр 12, 18) |

- **Happy path:** `transfer-nc.txt`-д ганц (`Valid Valid Normal Different None`), харин `transfer.txt`-д **нэг ч алга** — хязгаарлалт нэмснээр PICT мөрүүдийг өөрөөр баглаж, бүх утга хүчинтэй мөр санамсаргүйгээр алга болсон. Pairwise нь "бүх утга хүчинтэй" хослолыг огт баталгаажуулдаггүй гэсэн үг.
- **Олон алдаа:** nc ба IF хувилбарт 14 мөрийн 11 нь 2–3 алдаатай. Жишээ нь `transfer.txt`-ийн 10-р мөр `Frozen SameAsFrom OverBalance Same Partial` — давуу эрэмбээр сервер `ERROR_FROZEN` буцаагаад `SameAsFrom`, `OverBalance`-ийг огт шалгахгүй. Цаасан дээр "хамрагдсан" `(SameAsFrom, OverBalance)` хос үнэндээ шалгагдаагүй — энэ бол error masking.
- **Утгагүй мөр:** `transfer-nc.txt`-ийн 3, 8, 11-р мөрөнд байхгүй данс `Different` валют, `Partial` хэрэглээтэй — A2-ын IF хязгаарлалт эдгээрийг арилгасан (`transfer.txt`-д 0).
- **`~` хувилбар:** мөр бүрд хамгийн ихдээ 1 алдаа, 4 мөр бүрэн хүчинтэй — алдааны мөр бүр яг нэг алдааны ангийг шалгадаг тул oracle нь эрэмбээс хамаарахгүй.

#### `~` хэрэглэхэд A2-ын хязгаарлалт хэрэгтэй хэвээр үү?

**Хэсэгчлэн.** A2-ын хоёр төрлийн хязгаарлалт `~`-тэй өөр өөрөөр харьцдаг:

1. **[ERROR] төрлийнх — илүүц болсон.** Зааврын жишээний `IF [From] = "Missing" THEN [Amount] = "Normal"` нь алдааг алдаатай хослуулахгүй гэсэн утгатай. `~` үүнийг автоматаар хийдэг: PICT нь мөр бүрд хамгийн ихдээ нэг сөрөг утга оруулна, `Amount`-ын цорын ганц эерэг утга нь `Normal` тул `~Missing` мөрөнд `Amount` заавал `Normal` болно (`transfer-neg.txt`-ийн 13-р мөр).
2. **[IF] (property) төрлийнх — хэрэгтэй хэвээр.** `~` нь "алдаа + алдаа"-г хаадаг ч "алдаа + утгагүй" хослолыг хаадаггүй: IF-гүй `transfer-neg-noif.txt`-д 12-р мөр (`~Missing ... Same Partial`) ба 18-р мөр (`~Missing ... Different None`) — байхгүй дансанд өнөөдрийн хэрэглээ, валют гэж байхгүй. IF-тэй `transfer-neg.txt`-д эдгээр арилж `~Missing` нэг л мөрөнд (`Same None`) үлдсэн. Мөрийн тоо хоёуланд **18** — IF хязгаарлалт ямар ч нэмэлт мөр шаардаагүй.

`transfer-neg`-ийн 18 мөр яагаад nc-ийн 14-өөс олон вэ? PICT-ийн баримт бичигт заасанчлан хүчинтэй утгын бүх хос **зөвхөн алдаагүй мөрөнд** хамрагдах ба сөрөг утга бүр бусад параметрийн бүх хүчинтэй утгатай хосолно. `Currency × DailyUsed` = 2 × 2 = 4 хос → 4 happy path мөр (2–5); 7 сөрөг утга (`From` 2, `To` 2, `Amount` 3) тус бүр `Currency`, `DailyUsed`-ийн 2 утгатай хосолж ойролцоогоор 2 мөр авна → 14 алдааны мөр (`~Missing` `From` IF-ээс болж 1, `~Zero` 3). Алдаа бие биенээ далдлахгүй болсны төлөөс нь 4 нэмэлт мөр.

#### PICT гаралтаас бодит тест кейс (Лаб 5-ын хэв маягаар)

Суурь өгөгдөл, ханш Хэсэг A-гийн хүснэгтээр (1 USD = 3,500 MNT). Хүлээгдэх утга нь давуу эрэмбээр. Тодорхойлолтод үлдэгдэл харах endpoint байхгүй тул oracle нь статус + `result`.

| # | Эх мөр | Setup | `POST /transfer` бие | Oracle |
|---|---|---|---|---|
| TC1 — happy path (хөрвүүлэлттэй) | `transfer-neg.txt` мөр 4: `Valid Valid Normal Different None` | `A100` MNT, үлдэгдэл 500,000, лимит 1,000,000, өнөөдөр 0 ашигласан; `B200` MNT | `{"from":"A100","to":"B200","amount":100,"currency":"USD"}` (= 350,000 MNT) | **201**, `result = "OK"` |
| TC2 — нэг алдаа (`~OverBalance`) | `transfer-neg.txt` мөр 9: `Valid Valid ~OverBalance Different Partial` | `A100` MNT, үлдэгдэл 500,000, лимит 1,000,000, өнөөдөр **300,000** ашигласан (үлдсэн лимит 700,000); `B200` | `{"from":"A100","to":"B200","amount":160,"currency":"USD"}` (= 560,000 MNT) | **200**, `result = "ERROR_INSUFFICIENT"` |
| TC3 — нэг алдаа (`~Missing` from) | `transfer-neg.txt` мөр 13: `~Missing Valid Normal Same None` | Зөвхөн `B200` MNT; `X999`-ийг үүсгэхгүй | `{"from":"X999","to":"B200","amount":100000,"currency":"MNT"}` | **200**, `result = "ERROR_NO_FROM"` |
| TC4 — олон алдаатай мөр | `transfer.txt` мөр 10: `Frozen SameAsFrom OverBalance Same Partial` | `F300` MNT **царцаагдсан**, үлдэгдэл 500,000, лимит 1,000,000, өнөөдөр 300,000 ашигласан (үлдсэн лимит 700,000 — `OverLimit` биш) | `{"from":"F300","to":"F300","amount":600000,"currency":"MNT"}` | **200**, `result = "ERROR_FROZEN"` |

- **TC2:** PICT-ийн хийсвэр `Partial`-ыг бодит тоо болгохдоо анхаарах шаардлага гарсан — A1-ийн төлөөлөх утга 700,000 ашигласан гэвэл үлдсэн лимит 300,000 болж 560,000 нь `LIMIT`-ийг ч зөрчөөд "нэг алдаатай" мөр хоёр алдаатай болно. Тиймээс 300,000 ашигласан гэж сонгосон. Нэрлэсэн дүн `160` нь үлдэгдлээс хамаагүй бага мэт харагдах ч хөрвүүлсний дараа хэтэрдэг — A3-ын S14-тэй ижил санаа.
- **TC4:** гурван алдаа зэрэг (`FROZEN`, `SAME_ACCOUNT`, `INSUFFICIENT`) — `from` эхэлж шалгагддаг тул `ERROR_FROZEN`. Энэ тест үнэндээ зөвхөн царцаалтыг шалгаж, үлдсэн хоёрыг нууна.

### B3 — Гараар (A3) ба PICT-ийн харьцуулалт

| Шалгуур | Гараар — category-partition (A3) | PICT |
|---|---|---|
| Алдааны семантик | **Илүү барина:** [ERROR] утга бүр тусдаа, давхар нөхцөлийг зориуд сонгож давуу эрэмбийг бэхжүүлдэг (S16–S18) | `~`-гүй бол алдааг алдаатай хольж далдална (nc, IF хувилбарт 14-өөс 11 мөр олон алдаатай); `~`-тэй ч SINGLE, хязгаарын утгыг илэрхийлж чадахгүй |
| Хосын хамралт | Баталгаагүй — дизайнерын анхаарлаас хамаарна; 18 мөрөнд ямар хос орхигдсоныг тоолох арга алга | **Баталгаатай:** хүчинтэй утгын бүх хосыг хамарна, `/s`-ээр тоолж болно (browser 81 хос), ижил модель → ижил гаралт |
| Хязгаарын / property утга | `= үлдэгдэл`, `= лимит` (S10, S11), хөрвүүлэлтийн чиглэл (S14, S15) зэрэг "сонирхолтой" утгыг шууд оруулна | Хийсвэр утга (`Partial`, `OverBalance`) — бодит тоо болгохдоо дахин бодох хэрэгтэй (TC2) |
| Happy path | Үргэлж S1 | Баталгаагүй — `transfer.txt`-д 0 мөр; `~`-тэй хувилбарт 4 |
| Зардал | Хүний цаг их, параметр нэмэгдэх тусам өсдөг | Модель бичихэд л цаг орно, параметр нэмэхэд мөр бага өснө |

**Дүгнэлт:** алдааны семантикийг гараар хийсэн category-partition илүү барьдаг, хосын хамралтыг PICT баталгаажуулдаг. Хамгийн сайн нь хослуулах — category-partition-оор сонголт, утга, [ERROR]/[IF], давуу эрэмбээ тогтоогоод, PICT-д `~` ба IF хязгаарлалтаар буулгаж үүсгэх, PICT илэрхийлж чадахгүй [SINGLE], хязгаарын утгуудыг гараар нэмэх.

## Дүгнэлт

`POST /transfer`-ийн тодорхойлолтоос код байхгүйгээр 8 сонголт гаргаж, хязгаарлалтаар бүрэн олонлогийг 2592 → 540 → 17 frame болгож, 18 спецификаци бичсэн бол PICT-ийг эх кодоос бүтээж browser-ийн 2-way 10, 3-way 20 мөр, шилжүүлгийн гурван моделиор 14 / 14 / 18 мөр гаргасан. Хамгийн их бодол шаардсан нь A1–A2 буюу сонголтуудыг тодорхойлох алхам байсан: `amount` нэг талбар боловч тэмдэг, үлдэгдэл, лимит гэсэн гурван өөр асуулт асуудаг, мөн "үлдэгдэл, лимитийг хөрвүүлсний дараах дүнгээр шалгана" гэсэн дүрмээс болж ханшийн чиглэл, өнөөдрийн хэрэглээ гэсэн хоёр далд орчны сонголт гарч ирсэн. Давуу эрэмбийг код байхгүй тул өөрөө тогтоох шаардлагатай байсан бөгөөд энэ шийдвэр давхар нөхцөлийн гурван спецификаци, PICT-ийн олон алдаатай мөрийн (TC4) oracle-ыг бүгдийг нь тодорхойлсон. Браузерын жишээнд PICT лекцийн 9 мөрийн оронд 10 мөр өгсөн нь greedy алгоритмын шинж — сүүлийн мөр ганцхан хосын төлөө нэмэгдсэн. Хамгийн гэнэтийн зүйл нь `transfer.model`-д IF хязгаарлалт нэмэхэд бүх утга хүчинтэй happy path мөр огт үгүй болсон явдал: pairwise нь хосыг баталгаажуулдаг ч "бүгд хүчинтэй" хослолыг баталгаажуулдаггүй. Хязгаарлалтгүй ба IF хувилбарын 14 мөрийн 11 нь 2–3 алдаатай байсан тул цаасан дээрх хосын хамралтын ихэнх нь error masking-аас болж бодит шалгалт болохгүй байсан. `~` тэмдэглэгээ нэг мөрөнд нэг л алдаа оруулж, 4 happy path мөр баталгаажуулсан бөгөөд үүний төлөөс нь 4 нэмэлт мөр байв; харин A2-ын IF төрлийн хязгаарлалт `~`-тэй ч хэрэгтэй хэвээр — түүнгүйгээр байхгүй данс валют, өнөөдрийн хэрэглээтэй хослосон 2 утгагүй мөр гарсан. PICT-ийн хийсвэр утгыг бодит тест кейс болгоход ч анхаарал хэрэгтэй болсон: `Partial` хэрэглээг A1-ийн 700,000-аар авбал TC2-ын "нэг алдаатай" мөр хоёр алдаатай болох байсан. Нийтэд нь гараар хийсэн арга алдааны семантик, хязгаарын утга, SINGLE-ийг барьдаг, PICT хосын хамралтыг механикаар баталгаажуулдаг тул нэг нь нөгөөгөө орлохгүй, харин category-partition-ий дүгнэлтийг PICT-ийн модель руу зөв буулгах нь хамгийн чухал ур чадвар гэдгийг ойлгосон.
