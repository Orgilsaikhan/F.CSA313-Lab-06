PICT-ийн эх кодыг лабын репоосоо **гадна** `~/tools/pict`-д clone хийж cmake-ээр бүтээсэн:

```bash
mkdir -p ~/tools && cd ~/tools && git clone https://github.com/microsoft/pict && cd pict
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release

cp build/cli/pict ~/.local/bin/     # sudo эрхгүй тул /usr/local/bin биш ~/.local/bin (PATH-д байгаа)
```

## Хэсэг A: Category-Partition гараар — `POST /transfer`

```
POST /transfer  { "from": ID, "to": ID, "amount": NUM, "currency": CODE }
```

Код байхгүй, зөвхөн тодорхойлолт (shift-left). Тест бүрийн setup-ыг доорх суурь өгөгдлөөр тайлбарлана:

| Данс | Валют | Үлдэгдэл | Өдрийн лимит | Төлөв |
|---|---|---|---|---|
| `A100` | MNT | 500,000 | 1,000,000 | идэвхтэй — гол илгээгч |
| `B200` | MNT | 0 | 1,000,000 | идэвхтэй — гол хүлээн авагч |
| `F300` | MNT | 500,000 | 1,000,000 | **царцаагдсан** |
| `U400` | USD | 100 | 1,000 | идэвхтэй — USD данс |
| `X999` | — | — | — | **байхгүй** (ямар ч тест үүсгэдэггүй) |

Ханш: **1 USD = 3,500 MNT** (тест бүрт тогтмол гэж үзнэ).

### Алдааны давуу эрэмбэ

Тодорхойлолтод бичээгүй тул өөрөө тогтоосон:

```
ERROR_NO_FROM → ERROR_FROZEN → ERROR_NO_TO → ERROR_SAME_ACCOUNT → ERROR_BAD_AMOUNT → ERROR_INSUFFICIENT → ERROR_LIMIT
```

**Үндэслэл:** үлдэгдэл, лимит, валют бүгд `from` дансны өгөгдөл тул `from`-ийг эхэлж, дараа нь `to`-г, хамгийн сүүлд эдгээрээс хамаардаг `amount`-ыг шалгах ба `amount` дотроо данснаас хамааралгүй тэмдгийн шалгалт (`BAD_AMOUNT`) → одоогийн үлдэгдэл (`INSUFFICIENT`) → өдрийн хуримтлагдсан дүн (`LIMIT`) гэж хялбараас нь төвөгтэй рүү явна — Лаб 5-ын сервер ч мөн эхлээд оюутныг, дараа нь хичээлийг шалгадаг байсан.

| | | байхгүй | `X999` | [ERROR] |

| [property CONV] / [IF CONV] | C6 → C8 | Валют ижил бол хөрвүүлэлт байхгүй тул ханшийн чиглэл гэж байхгүй. |

### "N → M" тооцоо

**N — хязгаарлалтгүй бүрэн олонлог:** C1(3) × C2(4) × C3(3) × C4(3) × C5(3) × C6(2) × C7(2) × C8(2) = **2592**.

**IF хязгаарлалтын дараа:**

- C1 = байхгүй (FROM_EXISTS биш): C4–C8 утгагүй → C2(4) × C3(3) = **12**
- C1 ∈ {хүчинтэй, царцаагдсан}: C2(4) × C7(2) × (C6, C8)(ижил 1 + өөр×2 = 3) × [C3 ∈ {сөрөг, тэг} (2) + C3 = эерэг × C4(3) × C5(3) (9)] = 4 × 2 × 3 × 11 = 264, × 2 = **528**
- Нийт: 12 + 528 = **540**

**ERROR, SINGLE-ийн дараа:** [ERROR] 8 утга → 8 frame, [SINGLE] 3 утга → 3 frame. Үлдсэн хэвийн утгууд: C1 хүчинтэй × C2 өөр данс × C3 эерэг × C4 бага × C5 бага × (C6, C8) 3 × C7 2 = 6 frame. Нийт 6 + 8 + 3 = **17**.

```
2592 → 540 (IF) → 17 (ERROR, SINGLE)
```

### A3 — Спецификацийн хүснэгт

17 frame-ээс сонгоод, давхар алдааны 3 сонирхолтой хослол нэмсэн. "Хүлээгдэх" нь дээрх давуу эрэмбээр.

| # | Төрөл | C1 `from` | C2 `to` | C3–C5 `amount` | C6/C8 `currency` | C7 өнөөдөр ашигласан | Хүлээгдэх |
|---|---|---|---|---|---|---|---|
| S1 | Happy path | хүчинтэй `A100` | өөр `B200` | `100000` < үлдэгдэл < лимит | ижил `MNT` | 0 | **201** `OK` |
| S2 | ERROR C1 | байхгүй `X999` | өөр `B200` | `100000` | `MNT` | — | **200** `ERROR_NO_FROM` |
| S3 | ERROR C1 | царцаагдсан `F300` | өөр `B200` | `100000` | ижил `MNT` | 0 | **200** `ERROR_FROZEN` |
| S4 | ERROR C2 | хүчинтэй `A100` | байхгүй `X999` | `100000` | ижил `MNT` | 0 | **200** `ERROR_NO_TO` |
| S5 | ERROR C2 | хүчинтэй `A100` | ижил `A100` | `100000` | ижил `MNT` | 0 | **200** `ERROR_SAME_ACCOUNT` |
| S6 | ERROR C3 | хүчинтэй `A100` | өөр `B200` | `0` | ижил `MNT` | 0 | **200** `ERROR_BAD_AMOUNT` |
| S7 | ERROR C3 | хүчинтэй `A100` | өөр `B200` | `-5000` | ижил `MNT` | 0 | **200** `ERROR_BAD_AMOUNT` |
| S8 | ERROR C4 | хүчинтэй `A100` | өөр `B200` | `600000` > үлдэгдэл 500,000, < лимит | ижил `MNT` | 0 | **200** `ERROR_INSUFFICIENT` |
| S9 | ERROR C5 | хүчинтэй `A100` | өөр `B200` | `400000` ≤ үлдэгдэл, > үлдсэн лимит 300,000 | ижил `MNT` | хэсэгчлэн 700,000 | **200** `ERROR_LIMIT` |
| S10 | SINGLE C4 | хүчинтэй `A100` | өөр `B200` | `500000` = үлдэгдэл | ижил `MNT` | 0 | **201** `OK` (үлдэгдэл 0 болно) |
| S11 | SINGLE C5 | хүчинтэй `A100` | өөр `B200` | `300000` = үлдсэн лимит | ижил `MNT` | хэсэгчлэн 700,000 | **201** `OK` |
| S12 | SINGLE C2 | хүчинтэй `A100` | царцаагдсан `F300` | `100000` | ижил `MNT` | 0 | **201** `OK` (тодорхойлолт `to`-г хориглоогүй) |
| S13 | Хөрвүүлэлт (C8 их) | хүчинтэй `A100` (MNT) | өөр `B200` | `100` USD = 350,000 MNT < үлдэгдэл | өөр `USD` | 0 | **201** `OK` |
| S14 | Хөрвүүлэлт + ERROR C4 | хүчинтэй `A100` (MNT) | өөр `B200` | `200` USD = **700,000 MNT** > үлдэгдэл 500,000 | өөр `USD` | 0 | **200** `ERROR_INSUFFICIENT` |
| S15 | Хөрвүүлэлт (C8 бага) | хүчинтэй `U400` (USD, үлдэгдэл 100) | өөр `B200` | `300000` MNT ≈ 85.71 USD < үлдэгдэл 100 | өөр `MNT` | 0 | **201** `OK` |
| S16 | Давхар: C1 + C2 | царцаагдсан `F300` | байхгүй `X999` | `100000` | ижил `MNT` | 0 | **200** `ERROR_FROZEN` |

**Хамралт:** happy path 1 (S1), алдааны анги бүр — `NO_FROM` S2, `FROZEN` S3, `NO_TO` S4, `SAME_ACCOUNT` S5, `BAD_AMOUNT` S6–S7, `INSUFFICIENT` S8, `LIMIT` S9; SINGLE 3 (S10–S12); хөрвүүлэлтийн property 3 (S13–S15); давхар нөхцөл 3 (S16–S18) — **нийт 18**.

**Сонирхолтой нь S14 ба S15:** S14-д нэрлэсэн дүн `200` нь үлдэгдэл `500,000`-аас хамаагүй бага мэт харагдах ч хөрвүүлсний дараа хэтэрдэг, S15-д эсрэгээрээ нэрлэсэн `300,000` нь `100` USD үлдэгдлээс "их" мэт боловч хөрвүүлбэл багтана. Хөрвүүлэлтээс өмнө харьцуулдаг алдаатай хэрэгжүүлэлтийг эдгээр хоёр л барина.

**Давхар нөхцөл:** S16, S18 нь `from` → `to` → `amount` эрэмбийг, S17 нь `amount` доторх `INSUFFICIENT` → `LIMIT` эрэмбийг бэхжүүлнэ — хэрэгжүүлэлт өөр эрэмбээр шалгавал API-гийн хэрэглэгч өөр алдааны код хардаг тул эдгээр тест унах ёстой.
